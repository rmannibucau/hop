= Kubernetes Run

== Description

The *Kubernetes Run* action runs a container image as a Kubernetes *Job* and, optionally, waits for it to
complete, using a xref:metadata-types/kubernetes/kubernetes-connection.adoc[Kubernetes Connection].

The Job can be tuned with completion and parallelism counts, a backoff limit, a TTL for finished jobs and an
active deadline. When waiting for completion, the action polls the Job status and can delete the Job
afterwards.

== Options

[options="header", width="90%", cols="1,3"]
|===
|Option|Description
|Kubernetes connection|Name of the Kubernetes connection metadata to use.
|Image|The container image to run.
|Command|The container command to execute.
|Arguments|Arguments to pass to the command.
|Name / Job name|The name of the Job to create.
|Completions|Number of expected completions for the Job.
|Parallelism|Number of pods to run in parallel.
|Backoff limit|Number of retries before the Job is marked failed.
|TTL seconds|Time-to-live after which a finished Job is deleted.
|Active deadline (seconds)|Optional maximum run time for the Job.
|Namespace|The namespace in which to create the Job.
|Wait for completion|When enabled, polls the Job until it succeeds or fails.
|Delete on success|When enabled and waiting, delete the Job once it has completed.
|Timeout (seconds)|Maximum time to wait for completion before failing.
|Await field (JSON pointer)|Optional JSON pointer to a field to evaluate when waiting, so any "unknown" kind can be awaited. For example `/status.applicationState.state`.
|Await value|The expected, stringified value of the await field. For example `Completed`.
|===
