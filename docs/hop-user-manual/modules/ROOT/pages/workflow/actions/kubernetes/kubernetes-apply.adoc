= Kubernetes Apply

== Description

The *Kubernetes Apply* action creates or updates Kubernetes resources from one or more YAML or JSON
manifests using a xref:metadata-types/kubernetes/kubernetes-connection.adoc[Kubernetes Connection].

The manifest source can be:

* a single manifest *file*,
* a *folder* containing one or more manifest files (`.yaml`, `.yml`, `.json`, `.tpl`), or
* an *inline manifest*.

Each resource is created if it does not exist, or updated if it already exists. When the manifest is a
Deployment and wait-readiness is enabled, the action polls until the rollout is complete.

== Options

[options="header", width="90%", cols="1,3"]
|===
|Option|Description
|Kubernetes connection|Name of the Kubernetes connection metadata to use.
|Manifest file|Path to a single manifest file to apply.
|Folder|Path to a folder whose manifest files are applied (all supported files are considered).
|Inline manifest|The manifest content entered directly in the action, instead of a file or folder.
|Namespace|Overrides the namespace for resources that do not declare one.
|Wait ready|When enabled, waits for all deployment rollouts referenced by the manifests to complete.
|Rollout timeout (seconds)|Maximum time to wait for a rollout to complete before failing.
|Await field (JSON pointer)|Optional JSON pointer to a field to evaluate when waiting, so any "unknown" kind can be awaited. For example `/status.applicationState.state`.
|Await value|The expected, stringified value of the await field. For example `Completed`.
|===

== Awaiting custom resources

When *Wait ready* is enabled and an *Await field* / *Await value* pair is provided, the action polls the
applied resource and waits until the value at the JSON pointer equals the expected value (compared as
strings). This makes it possible to await workloads that are not special-cased by the action.

TIP: Apache Spark operators expose a *SparkApplication* CR. To wait for completion, set Await field to
`/status.applicationState.state` and Await value to `Completed`.
