= Kubernetes Rollout

== Description

The *Kubernetes Rollout* action manages rollout state for a workload (Deployment, StatefulSet or DaemonSet)
using a xref:metadata-types/kubernetes/kubernetes-connection.adoc[Kubernetes Connection].

Supported operations:

* *restart* - trigger a rolling restart by annotating the pod template,
* *status* - report the current rollout status and conditions,
* *wait* - poll until the workload reaches the desired condition (for example `Available`).

== Options

[options="header", width="90%", cols="1,3"]
|===
|Option|Description
|Kubernetes connection|Name of the Kubernetes connection metadata to use.
|Kind|The workload kind: `Deployment`, `StatefulSet` or `DaemonSet`.
|Name|The name of the workload.
|Namespace|The namespace of the workload.
|Operation|One of `restart`, `status` or `wait`.
|Desired status|The condition type to wait for when the operation is `wait` (for example `Available`).
|Timeout (seconds)|Maximum time to wait for the desired status.
|Await field (JSON pointer)|Optional JSON pointer to a field to evaluate for the `wait` operation, so any "unknown" kind can be awaited. For example `/status.applicationState.state`.
|Await value|The expected, stringified value of the await field. For example `Completed`.
|===

== Awaiting custom resources

When the operation is `wait` and an *Await field* / *Await value* pair is provided, the action polls the
workload and waits until the value at the JSON pointer equals the expected value (compared as strings),
instead of the built-in condition check. This makes it possible to await resources that are not special-cased
by the action.

TIP: Apache Spark operators expose a *SparkApplication* CR. To wait for completion, set Await field to
`/status.applicationState.state` and Await value to `Completed`.
