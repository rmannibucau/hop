= Kubernetes Apply

== Description

The *Kubernetes Apply* transform reads a YAML or JSON manifest from an input field for each incoming row and
creates or updates the corresponding Kubernetes resource, using a
xref:metadata-types/kubernetes/kubernetes-connection.adoc[Kubernetes Connection].

== Options

[options="header", width="90%", cols="1,3"]
|===
|Option|Description
|Kubernetes connection|Name of the Kubernetes connection metadata to use.
|Manifest field name|The name of the input field that contains the manifest.
|Namespace|Overrides the namespace for resources that do not declare one.
|Output field name|Name of the output field that receives the result (`Created`, `Updated`, `Unchanged` or an error). Default `result`.
|Wait ready|When enabled, waits for deployment rollouts referenced by each manifest to complete.
|Wait timeout (seconds)|Maximum time to wait for a rollout before failing.
|Await field (JSON pointer)|Optional JSON pointer to a field to evaluate when waiting, so any "unknown" kind can be awaited. For example `/status.applicationState.state`.
|Await value|The expected, stringified value of the await field. For example `Completed`.
|===

== Awaiting custom resources

When *Wait ready* is enabled and an *Await field* / *Await value* pair is provided, the transform polls the
applied resource and waits until the value at the JSON pointer equals the expected value (compared as
strings). This makes it possible to await workloads that are not special-cased by the transform.

TIP: Apache Spark operators expose a *SparkApplication* CR. To wait for completion, set Await field to
`/status.applicationState.state` and Await value to `Completed`.
